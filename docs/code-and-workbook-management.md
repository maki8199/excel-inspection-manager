# Excel/VBA開発のコード・フォーム・シート管理ガイド（汎用）

## この文書について

Windows版ExcelとVBAで作る業務ツールを、人間とAIエージェントがGit上のテキストとして管理し、スクリプトでExcelブックへ組み立てるための方針です。特定の業務・リポジトリ・個人環境には依存しません。

- 本書は方針と構成例です。記載したスクリプトやフォルダは作成済みではなく、導入先で実装し、対象のWindows版Excelで検証してから運用します。
- 業務要件・入力権限・保存期間などは導入先の要件書で定めます。本書を他案件へ持ち出す際、元案件の要件書は不要です。
- 開発手順は、本番データの直接編集を許可するものではありません。
- AIエージェントが守る規則は第11節、スクリプトの入出力は第10節にまとめています。

## 1. 基本方針

管理対象ごとに、編集・復元の基準となる正本を一つだけ決めます。同じ内容をJSONとExcelの両方で正本にするような二重管理はしません。

| 管理対象 | 正本 | Excelへの反映方法 |
|---|---|---|
| 標準モジュール | 属性を含む `.bas` | Import |
| 独自クラスモジュール | 属性を含む `.cls` | Import |
| ThisWorkbook・シートのコード | コード本文だけの `.vba` | 既存モジュールの本文を置き換え |
| UserForm（画面とコード） | `.frm`＋`.frx`（初回生成後） | Import |
| シートの見た目・構造 | Excelひな形 | ビルドの土台として使用 |
| 本番データ | 開発フォルダ外の所定の保管先 | アプリの更新とは分離 |

- **ひな形にはコードを持たせません。** コードとフォームはすべて `src/` から組み込みます（第5節）。
- 発行済みブックで行ったシートの見た目・構造の編集は正本へ取り込みません。シートの変更はひな形側で行います。
- 変更前の一式（ひな形・コード・フォーム）を残したまま次版候補を作り、確認してから採用します。

## 2. 実行環境

- 作業はすべてWindowsで行います。ソースの編集、ビルド・抽出・検証は、Windows版デスクトップExcelが入った端末の、ログイン中の対話セッションで実行します。AIエージェントも同じWindows端末上で動かし、PowerShellスクリプトを呼び出します。macOSやLinuxでの作業は対象外です。サービスやログオフ状態での無人実行は対象外です。
- 実装は社内で許可されたPowerShell（標準搭載のWindows PowerShell 5.1を基本）とExcel COM/VBIDEで行います。Goや外部配布の実行ファイルは前提にしません。
- Excelの「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」を有効にする必要があります。有効にするのは開発用端末に限り、導入先の許可を得ます。
- スクリプトは処理専用のExcelインスタンスを `New-Object -ComObject Excel.Application` で起動し、ユーザーが開いているExcelには接続しません。終了時はブックを閉じて `Quit` し、COMオブジェクトを解放します。後始末とタイムアウトの扱いは第10節に従います。

### Excelの開き方：組み立て・抽出と動作検証を分ける

プログラムからブックを開くと、既定ではマクロが有効です。コードを取り出すだけの操作で `Workbook_Open` などが動き、業務処理や外部ファイルへの書き込みが起きないよう、工程を二つに分けます。

| 工程 | 対象 | マクロ | 目的 |
|---|---|---|---|
| 組み立て・抽出 | ひな形のコピー、取り込み対象ブックのコピー | 無効 | コード・フォームの組み込みと書き出し |
| 動作検証 | 組み立て済みの候補ブック | 有効 | 自動テスト・動作確認 |

組み立て・抽出では、ブックを開く前に次を設定します。

- `Application.AutomationSecurity = 3`（msoAutomationSecurityForceDisable）
- `Application.EnableEvents = False`
- `Application.DisplayAlerts = False`、`Application.AskToUpdateLinks = False`
- `Workbooks.Open` の `UpdateLinks` を `0`（外部リンクを更新しない）
- 抽出対象は `work/` へコピーしてから、読み取り専用で開く

動作検証は、組み立てを終えて保存した候補ブックを、別に起動したインスタンスでマクロ有効にして開きます。検証では検証用のブック・データだけを使い、本番データを参照・変更しません。

## 3. フォルダ構成

以下は構成例です。UserFormや独自クラスを使わない案件では該当フォルダを省略できます。

```text
excel-vba-project/
├── README.md                         # 開発環境・ビルド・編集・復元の入口
├── .gitignore
├── .gitattributes                    # 改行・バイナリの扱い（第4節）
├── docs/
│   ├── requirements.md               # 導入先の業務要件
│   ├── code-and-workbook-management.md # 本ガイドまたは案件への適用方針
│   └── release-notes.md              # 版ごとの変更内容・確認結果
├── templates/
│   └── application.xlsm              # シートの見た目・構造の正本（コードなし）
├── src/
│   ├── modules/
│   │   ├── AppMain.bas               # 標準モジュール
│   │   └── Validation.bas
│   ├── classes/
│   │   └── Record.cls                # 独自クラス
│   ├── workbook/
│   │   └── ThisWorkbook.vba          # ブックのコード本文
│   ├── worksheets/
│   │   ├── SheetMain.vba             # シートのコード本文（ファイル名＝CodeName）
│   │   └── SheetHistory.vba
│   ├── forms/
│   │   ├── EntryForm.frm             # フォーム（コードを含む）
│   │   └── EntryForm.frx
│   └── unmanaged.txt                 # 管理対象外の例外がある場合だけ（第5節）
├── bootstrap/                        # フォームの初回生成中だけ存在（第6節）
├── scripts/
│   ├── build.ps1                     # 正本から候補ブックを組み立てる
│   ├── export-edits.ps1              # 編集済みブックからコード・フォームを書き出す
│   ├── verify.ps1                    # 構成チェックと自動テスト
│   ├── describe-forms.ps1            # フォームの部品一覧を書き出す（第6節）
│   └── invoke-with-timeout.ps1       # 本体を起動して時間切れを見張る（第10節）
├── tests/
│   ├── acceptance.md                 # 動作・見た目の確認チェックリスト
│   ├── vba/                          # 自動テスト用のモジュール（配布物には含めない）
│   └── fixtures/                     # 自動テスト用の架空データ
├── work/                             # 作業用コピー・書き出し結果・候補版
└── dist/
    └── application.xlsm              # 生成物。検証合格前は配布しない
```

| 場所 | 内容 | Git管理 |
|---|---|---|
| `README.md`、`docs/` | 手順・要件・版の記録 | 対象 |
| `templates/` | シートの正本。`work/` にコピーして編集し、確認後に採用（第7節） | 対象 |
| `src/` | コード・フォームの正本 | 対象 |
| `scripts/` | ビルド・書き出し・検証。ひな形や本番データを上書きしない | 対象 |
| `tests/` | チェックリスト、テスト用モジュール、架空データ。本番ファイルのコピーを置かない | 対象 |
| `work/` | 作業用。正本ではない | 対象外 |
| `dist/` | 生成したブック。正式配布物の保管先とは別 | 対象外 |

`templates/application.xlsm` はシートの正本、`dist/application.xlsm` はコード・フォームを組み込んだ生成物です。`dist/` のブックをひな形として使いません。

スクリプト名と役割は設計例です。小さな案件では一つのスクリプトにまとめてもかまいません。

### Git設定の例

```gitignore
# 作業用コピー・生成物
/work/
/dist/

# Excelの一時ファイル・OSの管理ファイル
~$*
*.tmp
.DS_Store
Thumbs.db

# 個別環境の設定・認証情報
.env
.env.*
!.env.example
*.local.*

# 本番データ等を誤って置いた場合の補助的な除外
/production-data/
/backups/
```

```gitattributes
*.bas  text eol=crlf
*.cls  text eol=crlf
*.frm  text eol=crlf
*.vba  text eol=crlf
*.frx  binary
*.xlsm binary
*.xlsx binary
```

- `*.xlsm` や `*.frx` を一律に除外すると、正本のひな形やフォームまで管理できなくなるため除外しません。
- `work/` や `dist/` はGit管理外ですが、正本への採用や正式保管が済む前に削除しません。
- 除外設定は、追跡済みファイルの機密情報除去やバックアップの代わりになりません。コミット前に対象を確認します。

開発・運用には、社内で承認された保存先と版管理環境を使います。本書でいうGitによる版管理は公開GitHubへのアップロードを意味せず、**公開リポジトリは使いません。** 具体的な製品・保存先は導入先で決めます。

### 開発フォルダの外に置くもの

本番データとバックアップは、社内で承認された別の保管先へ置きます。具体的なパスや保存方式は導入先で決めます。

```text
社内の承認済み保管先/
├── releases/          # 検証済み配布物。版・元コミットと対応付ける
├── production-data/   # 運用中のデータ。ソース管理へ入れない
└── backups/           # 本番データの復旧用。ソースの履歴とは別管理
```

三つを同じ物理的な場所に置く必要はありません。個人情報・認証情報・実業務データ・端末固有の接続設定を、ひな形や共有するソースへ混在させません。

## 4. 文字コードと改行

リポジトリとExcelでは文字コードが異なるため、スクリプトが境界で変換します。

| 場所 | 文字コード | 改行 |
|---|---|---|
| リポジトリ（`src/`、`bootstrap/`） | UTF-8（BOMなし） | CRLF |
| VBEのImport／Export | システムのANSIコードページ（日本語WindowsではCP932） | CRLF |

- **前提の確認：** スクリプトの開始時に、システムのANSIコードページが932であることを確認し、違えば停止します。Windowsの「ベータ: ワールドワイド言語サポートでUnicode UTF-8を使用」が有効な環境も停止対象です。
- **Import（`.bas`・`.cls`・`.frm`）：** UTF-8のソースを読み、CP932に変換した一時ファイルを `work/` に作ってからImportします。CP932で表せない文字があれば、ファイル名と行を報告して停止します。別の文字へ置き換えません。
- **Export：** `work/` の一時フォルダへExportし、CP932として厳密に読み込み、UTF-8（BOMなし）で保存します。
- **Documentモジュール（`.vba`）：** COM経由の文字列は変換不要ですが、VBE内部はCP932のため、同じくCP932で表せない文字があれば停止します。
- **`.frx`：** バイナリのため変換しません。
- **BOM：** `src/` のファイルにBOMがあれば停止します。BOM付きのまま取り込むと、先頭行の `Attribute VB_Name` が壊れます。
- **PowerShellの注意：** `Get-Content`・`Set-Content` の既定の文字コードに頼りません。Windows PowerShell 5.1の `-Encoding UTF8` はBOMを付けます。読み書きは .NET の `System.Text.Encoding` を明示して行い、CP932の変換では変換不能文字で例外を出す設定にします。
- **改行：** `.gitattributes` でCRLFに固定します。LF改行の `.bas` をImportすると、`Attribute` 行がコードとして扱われて壊れます。

日本語を含むコードが往復で変わらないことは、第8節の初回実機検証で確認します。

## 5. VBAコードの管理

### 標準モジュール・独自クラス

`.bas`・`.cls` を正本とし、コード本文だけでなくヘッダーと `Attribute` 行も保持します。人間やAIはこのテキストを直接編集できます。

`Attribute` 行（属性）は、VBEのコード画面には表示されず、Exportしたファイルにだけ現れる設定です。モジュール名（`VB_Name`）や既定インスタンス（`VB_PredeclaredId`）などのモジュール全体の設定と、既定メンバー（`Item.VB_UserMemId = 0`）や説明文（`VB_Description`）などのプロシージャ単位の設定があります。


- `Attribute` 行を不要情報として削除しません。既定インスタンス・既定メンバーなど、属性に依存する動作も復元対象です。
- 拡張子を除くファイル名と、ファイル内の `Attribute VB_Name` を一致させます。
- 新規モジュールは、対象Excelで確認したエクスポート形式を基にファイルを作るか、初回だけCOMで作成してExportします。本文だけの別ファイルを並行して残しません。

### ThisWorkbook・シートのコード

`src/workbook/`・`src/worksheets/` の `.vba` は、ブック・シートオブジェクトのコード本文だけを保存します。シートの見た目・テーブル構造・名前定義はひな形で管理します。

- ビルド時は、ひな形内の既存Documentコンポーネントを特定し、その `CodeModule` の本文を `.vba` の内容で置き換えます。通常のクラスをImportして代わりにすることはしません。
- 書き出し時は、`CodeModule` から本文を読んで `.vba` に保存します。
- シートの `.vba` のファイル名はCodeNameとし、タブ名と混同しません。
- `.vba` は本文保存用に採用した拡張子で、拡張子自体に特別な機能はありません。標準・クラスの正本には使いません。
- ThisWorkbook・シートのモジュールでは、**プロシージャ単位の属性を使いません。** `CodeModule` で読み書きする本文には `Attribute` 行が含まれず、本文の置き換えで黙って消えるためです。
- 検出するときは、該当コンポーネントを `work/` の一時フォルダへ `VBComponent.Export` し、`Attribute 名前.設定 = 値` の形（プロシージャ名が付いたもの）の行があれば、終了コード3で停止します。モジュール全体の設定（`VB_Name`・`VB_Base` など、Excelが自動で付けるもの）は対象外です。
- この確認は取り込み時（第9節）に行います。ビルドでは空のモジュールへ本文を書き込むだけなので、属性が入り込むことはありません。

### コーディング規約

- `value`・`name`・`item` など、組み込みのプロパティやメソッドと同じ綴りの変数名・引数名を使いません。VBEは同じ綴りの名前の大文字小文字をプロジェクト全体でそろえるため、関係ないモジュールの `.Value` が `.value` に書き換わり、意味のない差分が出ます（第9節）。

### 参照設定

参照設定（VBEの「ツール → 参照設定」で選ぶ外部ライブラリの一覧）は、コードのファイルではなくブックの中に保存されます。テキストで管理できず、PCによってライブラリの版が違うと「参照不可」になるため、**追加の参照設定は使いません。**

- 外部ライブラリは、実行時に `CreateObject` で呼び出します。変数の型は `Object` にします。

  ```vb
  Dim dict As Object
  Set dict = CreateObject("Scripting.Dictionary")
  ```

- ブックにあってよい参照設定は、Excelが自動で付ける次の五つだけです。

  | 名前（`Reference.Name`） | 内容 |
  |---|---|
  | `VBA` | Visual Basic For Applications |
  | `Excel` | Microsoft Excel Object Library |
  | `stdole` | OLE Automation |
  | `Office` | Microsoft Office Object Library |
  | `MSForms` | Microsoft Forms 2.0 Object Library（UserFormを組み込むと自動で付く） |

- これ以外の参照設定がある場合、または参照不可（`IsBroken`）のものがある場合は、終了コード3で停止します。確認するのは、ひな形の確認時、ビルド後の検証時、取り込み時（第9節）です。
- どうしても追加の参照設定が必要になった場合は、一覧をテキストで管理してビルド時に設定する方式へ切り替えます。その際は本節を改訂します。

### 管理対象の規約

ひな形にコードを持たせないことで、「削除した部品」と「管理対象外の部品」を区別する必要をなくします。

1. **ひな形には標準モジュール・クラス・UserFormを置かず、Documentモジュールも空にします。** ビルドは常にひな形から始めるため、削除・改名した旧部品が残りません。
2. **VBA部品は原則すべて管理対象です。** どうしてもひな形に残す部品（外部から支給されたモジュールなど）がある場合だけ、その部品名を `src/unmanaged.txt` に一行ずつ記載します。
3. **Documentモジュールは、コードが空でも `.vba` ファイルで表します。** ひな形のThisWorkbookと各シートには、対応する `.vba` がちょうど一つずつ必要です。シートを追加・削除したら `.vba` も追加・削除します。
4. **想定外のものがあれば停止します。** 次の場合は自動で補正せず、報告して人間の判断を待ちます。
   - ひな形に、`unmanaged.txt` にない標準・クラス・フォームがある。
   - ひな形のDocumentモジュールにコードが残っている。
   - Documentコンポーネントに対応する `.vba` がない、または `.vba` に対応するシートがない。
   - ファイル名と `Attribute VB_Name`、期待する種別と実際の種別が食い違う。
   - Import後の部品名が期待と異なる（同名があるとExcelは自動で別名を付けるため）。

ひな形・配布物とも、VBAプロジェクトのパスワード保護とブックの保護はかけません。保護があるとスクリプトからコードを読み書きできないため、検出したら終了コード3で停止します。

全モジュール名を別の対応表へ重複登録することはしません。名前と種別は、フォルダ・拡張子・ファイル名で決まります。

## 6. UserFormの管理

初回だけ定義とコードから自動生成し、その後はエクスポートした `.frm`＋`.frx` を正本にします。

### 段階1：初回生成

```text
bootstrap/forms/EntryForm/
├── layout.json    # フォームの大きさ、部品の種類・名前・位置・サイズ・表示文字
└── code.vba       # フォームのコード
```

```text
layout.json と code.vba からCOM経由でフォームを生成
  → .frm＋.frx へエクスポート
  → 別ブックへの取り込み・表示・動作を確認
  → src/forms/ の .frm＋.frx を正本にする
  → bootstrap/forms/EntryForm/ を削除する（Gitの履歴には残る）
```

`.frm`＋`.frx` を最初から手書きで作ることはしません。後から新しいフォームを追加する場合も、そのフォームだけ同じ手順を踏みます。

### 段階2：正本切り替え後の修正

フォームのコードは `.frm` に含めて管理し、別の `.vba` で重複管理しません。コードだけの修正なら、`.frm` のコード部分（`Attribute` 行より後ろ）をテキストとして直接編集してかまいません。ヘッダー部分は編集しません。

```text
正本の .frm＋.frx を作業用ブックへImport
  → 編集前の部品一覧を書き出す（下記）
  → 人間またはAIが編集する
  → 編集後の部品一覧を書き出し、編集前と比べる
  → 表示・操作を確認する
  → 再エクスポートして正本を更新する
```

- AIが修正する場合も、`.frx` のバイナリを直接書き換えず、Excel内のフォームをCOM経由で操作します。
- フォント変更・部品追加・配置変更なども同じ手順です。文字サイズを変えたら、文字切れや部品の重なりを確認します。
- フォームを作り直す場合は、既存のイベント処理・部品名・外部コードからの参照を引き継ぐか、明示的に変更します。古い `layout.json` を再利用して途中の編集を失わないようにします。

### 部品一覧の書き出し（describe-forms.ps1）

部品の種類・位置・サイズ・表示文字はバイナリの `.frx` に入っており、テキストとして読めません。そのままでは、AIは今のフォームの構成を把握できず、人はAIの変更をGitの差分で確認できません。そこで、Excel内のフォームをCOM経由で調べ、部品の一覧をテキストで書き出します。

```text
EntryForm  W=320 H=240 Font=Meiryo UI 9pt
fraBasic   Frame          L=6   T=6   W=300 H=80  Caption="基本情報"
  lblCode  Label          L=6   T=12  W=60  H=12  Caption="コード"
  txtCode  TextBox        L=70  T=10  W=120 H=18  TabIndex=0
cmdSave    CommandButton  L=230 T=200 W=72  H=24  Caption="保存"
```

- **出力する項目：** 名前、種類、親子関係（字下げで表す）、位置、サイズ、表示文字、タブ順、フォント。
- **出力するタイミング：** フォームを編集するとき（初回生成を含む）に、編集の前と後で書き出します。ビルドのたびには出しません。
- **使い道：** AIは編集前の一覧で現状を把握し、編集後の一覧で意図どおりに変わったかを確かめます。人は前後の一覧の差分でレビューします。
- **位置づけ：** `work/` に出力する確認用の生成物です。正本は `.frm`＋`.frx` のままで、一覧をGit管理や編集の対象にしません。
- **画面の拡大率：** フォームのExportと一覧の書き出しは、Windowsの表示の拡大率が100%の端末で行います。拡大率が違うとフォームのサイズ値がずれ、意味のない差分が出るためです。スクリプトは開始時に拡大率を確認し、100%でなければ終了コード4で停止します。
- 画面の画像は撮りません。必要になった時点で追加を検討します。

## 7. シート（ひな形）の管理

シートの見た目・構造はExcelひな形を正本にします。ひな形で管理するのは次のものです。

- セルの固定文言、書式、色、罫線
- 列幅、行高、レイアウト
- 図形やボタンの配置
- テーブルの構造、名前定義
- 印刷設定など

### 変更の流れ

```text
templates/ のひな形を work/ へコピー
  → コピーをExcelで編集する（コードは書かない）
  → そのコピーと src/ から候補ブックを組み立てる（第8節）
  → 表示・動作を確認する
  → 問題なければ、編集したひな形のコピーを templates/ へ採用する
```

- 採用するのは**編集したひな形のコピー**です。コードを組み込んだ候補ブックをひな形にしません。
- 採用前に、第5節の規約（コードがないこと）を満たしているか確認します。編集中にコードを書いてしまった場合は、第9節の手順で `src/` へ移してから採用します。
- テーブル名・列名・名前定義・部品名を変えた場合は、それを参照するコードへの影響を確認します。
- 同じレイアウトをJSONにも記述する必要はありません。

### 発行済みブックのシート編集

発行済みブックで行った色・配置・固定文言・テーブル構造・名前定義などの変更は、正本へ取り込みません。差分抽出や逆取り込みの仕組みも作りません。必要な修正はひな形側で行います。

この制限はシートの見た目・構造の編集に対するものです。業務仕様で認められたデータの登録・更新は通常どおり行えます。

## 8. ビルドと検証

### ビルドの流れ（build.ps1）

```text
ひな形を work/ の新しいフォルダへコピー
  → マクロ無効で開く（第2節）
  → 管理対象の規約を満たすか確認する（第5節）。違反があれば停止
  → .bas・.cls・.frm を文字コード変換して Import（第4節）
  → ThisWorkbook・シートのモジュールへ .vba の本文を反映
  → 名前・種別・必要な属性・参照設定を確認
  → コミット番号と未コミットの変更の有無をブックに記録（第9節）
  → .xlsm として保存し、Excelを終了
  → 動作検証（下記）
  → 合格したものを dist/ へ置く
```

失敗した候補は、正本や配布物として採用しません。書き出し先・作業先は未使用のフォルダを選び、既存の検証結果や正本を上書きしません。

**ユーザーに渡すブックは、未コミットの変更がない状態でビルドしたものに限ります。** 未コミットの変更を含む候補は、AIの試行・確認用です。

### 検証（verify.ps1）

**構成のチェック**

- ひな形が存在し、第5節の規約を満たしている。
- フォームが参照する `.frx` がそろっている。
- `src/` のファイルがUTF-8（BOMなし）・CRLFで、CP932で表せない文字を含まない。
- 組み立て後のブックに、必要なモジュール・フォームが期待どおりの名前・種別で存在する。
- ブック・シートのコードが正しいDocumentコンポーネントに入っている。
- 参照設定が、第5節で認めたものだけになっている。

**自動テスト**（候補ブックをマクロ有効で開いて実行）

- 計算処理：決めた入力を渡し、期待結果と比較する。
- 保存処理：検証用ブックへ保存し、開き直して値が残っているか確認する。

テストを実装していない機能は未検証として扱います。テストの書き方は下の「自動テストの書き方」に従います。

**人による確認**

`tests/acceptance.md` のチェックリストに沿って、対象のWindows版Excelで確認します。確認結果と未確認項目を区別して記録します。

- コンパイルが通る（自動確認できないため、当面は人が確認する。第10節）。
- ボタンから目的の処理・フォームが開き、イベントが動作する。
- 変更した機能が動き、変更していない主要機能が壊れていない。
- 保存・再起動後も期待する状態を保持する。
- シートやフォームに文字切れ・重なり・操作しづらさがない。

### 自動テストの書き方

テスト用のコードは配布物に含めず、検証のときだけ組み込みます。

```text
tests/
├── acceptance.md
├── vba/
│   ├── Test_Calc.bas          # テスト用の標準モジュール
│   └── Test_Save.bas
└── fixtures/                  # テスト用の架空データ
```

| 項目 | 約束 |
|---|---|
| 置き場所 | `tests/vba/`。`src/` には置かない |
| モジュール名 | `Test_<対象>`（例：`Test_Calc`）。半角英数字と `_` を使う |
| プロシージャ名 | `Test_<確認する内容>`（例：`Test_ToleranceUpperLimit`） |
| 形 | 引数なしの `Public Function ... As String` |
| 戻り値 | 合格なら空文字 `""`、失敗なら理由を書いた文字列 |

```vb
Public Function Test_ToleranceUpperLimit() As String
    On Error GoTo Failed
    Dim actual As Double
    actual = Validation.UpperLimit(10, 0.5)
    If actual <> 10.5 Then Test_ToleranceUpperLimit = "期待 10.5、実際 " & actual
    Exit Function
Failed:
    Test_ToleranceUpperLimit = "エラー " & Err.Number & ": " & Err.Description
End Function
```

- テストの中で `MsgBox` などのダイアログを出しません。エラーは必ず `On Error` で受けて、戻り値で返します。処理されないエラーはダイアログを出し、Excelが固まるためです。
- `verify.ps1` は、候補ブックを `<OutDir>` へコピーし、そのコピーに `tests/vba/` のモジュールをImportします。`tests/fixtures/` も `<OutDir>/fixtures/` へコピーします。元の候補ブックは変更しません。
- テストは、`tests/vba/` のファイルから `Public Function Test_` で始まるプロシージャを探し、`Application.Run "モジュール名.プロシージャ名"` で一つずつ実行します。一覧表への登録は不要です。
- テストが架空データを使うときは、`ThisWorkbook.Path & "\fixtures"` を参照します。本番データの場所を参照しません。
- 一つのテストが `result.json` の一項目になり、テストを一つ終えるたびに `progress.json` を更新します（第10節）。

### 初回の実機検証

運用開始前に、日本語入りの標準モジュール、属性を使う独自クラス、ブック・シートのイベント、UserFormを含む小さな検証ブックで、次を一周させます。

```text
組み立て → VBEで修正 → work/ へ書き出し → 比較・採用 → 再構築 → 保存・再起動
```

本文だけでなく名前・種別・属性・文字コードと動作が保たれること、旧版一式へ戻せること、途中で失敗しても原本が変わらないことを確認します。あわせて、各手順にかかった時間を記録し、タイムアウトの値を見直します（第10節）。

## 9. Excel内で直接変更したコード・フォームの取り込み

Excel内でコードやUserFormを修正した場合は、そのブックだけで終わらせず、対応する正本へ戻します。取り込みは自動同期ではなく、AIが担当し、衝突や意図が曖昧な変更だけ人間に確認します。シートの見た目・構造は対象外です（第7節）。

### 書き出し（export-edits.ps1）

```text
編集済みブックを work/ へコピー
  → マクロ無効・読み取り専用で開く（第2節）
  → 取り込み元にできるブックか確認する（下記）。できなければ停止
  → すべてのコード・フォームを work/extracted/ へ書き出す
  → 比較元・ブック・現在の src/ の三つを比較する（下記）
  → 採用する変更だけ src/ へ反映する
  → 再ビルドして再現を確認する
```

変更箇所だけを自動で抜き出すのではなく、まず全部を書き出してから比較します。この段階では `src/` を上書きしません。

| 対象 | 書き出し方法 | 反映先 |
|---|---|---|
| 標準モジュール | `VBComponent.Export`（文字コード変換あり） | `src/modules/*.bas` |
| 独自クラス | `VBComponent.Export`（文字コード変換あり） | `src/classes/*.cls` |
| ThisWorkbook・シート | `CodeModule` から本文を読み取る | `src/workbook/`・`src/worksheets/` の `.vba` |
| UserForm | `VBComponent.Export` | `src/forms/*.frm`＋`.frx` |

ブックにあって `src/` にない部品は「新規追加」、`src/` にあってブックにない部品は「削除」として報告し、採用するか人間に確認します。

ブックに追加の参照設定が見つかった場合は、終了コード3で停止します（第5節）。そのライブラリを使うコードは、`CreateObject` で呼び出す形に直してから採用します。

### 取り込み元にできるブック

ブックには、ビルド時に次の二つをユーザー設定のドキュメントプロパティとして記録します。

| プロパティ名 | 内容 |
|---|---|
| `SourceCommit` | ビルドに使ったコミット番号 |
| `SourceUncommitted` | 未コミットの変更を含んでいたか（True／False） |

取り込み元にできるのは、`SourceUncommitted` が False で、`SourceCommit` のコミットがリポジトリに存在するブックだけです。プロパティがない、未コミットの変更を含む、コミットが見つからない場合は、終了コード3で停止します。

ユーザーに渡すブックはコミット済みの状態から作るため（第8節）、記録したコミットから「ブックを作った時点の正本」を必ず取り出せます。

### 比較の方法

ユーザーの変更と、ブックを渡した後に正本側で加えた変更を区別するため、次の三つを比較します。

1. 比較元：`SourceCommit` の時点の `src/`
2. ユーザーが変更したブックから書き出したもの
3. 現在の `src/`

| 比較元 → ブック | 比較元 → 現在の `src/` | 扱い |
|---|---|---|
| 変更あり | 変更なし | ユーザーの変更として採用する |
| 変更なし | 変更あり | 現在の `src/` を残す（古いブックで先祖返りさせない） |
| 変更あり | 変更あり（同じ箇所） | 衝突。人に確認する |

- `.frx` はバイナリで部分的に統合できないため、ブックと現在の `src/` の両方で変わっていれば衝突として扱います。
- 任意の変更を常に自動で正しく統合できるとは限りません。判断に迷う差分は人に確認します。

### 大文字小文字だけの差分

VBAは名前の大文字と小文字を区別しません。一方VBEは、同じ綴りの名前の表記をプロジェクト全体で一つにそろえるため、誰も触っていないモジュールでも名前の大文字小文字が変わることがあります（`.Value` → `.value` など）。これは動作に影響しない見た目だけの変化です。

- 比較の前に、改行と行末の空白をそろえます。
- **文字列とコメント以外の部分で、名前の大文字小文字だけが違う差分**は採用せず、`src/` 側の表記を残します。
- 文字列（`"ABC"` と `"abc"` は別の値）とコメントの中の大文字小文字の違いは、本物の変更として扱います。VBEはこの部分を書き換えないためです。

## 10. スクリプトの呼び出し仕様

AIエージェントが実行結果を毎回同じように判断できるよう、スクリプトの入力・出力を固定します。AIは画面に表示される文章ではなく、**終了コードと `result.json`** で結果を判断します。

### 引数

毎回同じもの（`src/` や `unmanaged.txt` の場所）は、リポジトリのルートを基準にスクリプト内で決めます。実行ごとに変わるものは**必須の引数**とし、既定値を付けません。渡し忘れたときに、別のファイルを使って処理が「成功」してしまうのを防ぐためです。

| スクリプト | 必須の引数 |
|---|---|
| `build.ps1` | `-Template`（組み立てに使うひな形）、`-OutDir`（出力先） |
| `verify.ps1` | `-Workbook`（検証する候補ブック）、`-OutDir` |
| `export-edits.ps1` | `-Workbook`（書き出し元の編集済みブック）、`-OutDir` |
| `describe-forms.ps1` | `-Workbook`（フォームを含む作業用ブック）、`-OutDir` |

```text
powershell -File scripts\invoke-with-timeout.ps1 -Script build.ps1 -Template work\edit-01\application.xlsm -OutDir work\build-20260930-1
```

Excelを操作するスクリプトは、直接ではなく見張り役の `invoke-with-timeout.ps1` を通して実行します（後述）。

- `-OutDir` には `work/` の下の新しいフォルダを指定します。すでに存在する場合は上書きせずに停止します（終了コード3）。
- 既定値は、省略しても正しく動くもの（タイムアウトの秒数など）に限ります。
- `build.ps1` の `-Version` は、発行するときだけ渡します。省略すると `dev` と記録されます（第12節）。

### 終了コード

スクリプトは自分で行った確認の結果から判断し、最後に次のいずれかを返します。

| コード | 意味 | AIの行動 |
|---|---|---|
| 0 | 成功 | 次の工程へ進む |
| 1 | 予期しないエラー（スクリプトの不具合など） | 止まって報告する |
| 2 | 検証の失敗（テスト・照合が不合格） | 原因を調べて `src/` を修正してよい |
| 3 | 規約違反などで停止（人の判断が必要） | 止まって人に確認する |
| 4 | 環境エラー（コードページ、Excelが起動できない、など） | 止まって報告する |
| 5 | タイムアウト | 止まって報告する |

- 1は、想定外の例外でPowerShellが自動的に返す値と同じです。スクリプトが意図して返す値には使いません。
- 2と3を区別します。2はAIが自分で直してよい失敗、3は人の判断が必要な停止です。

### 結果ファイル

各スクリプトは `<OutDir>/result.json` をUTF-8（BOMなし）で書き出します。

```json
{
  "script": "build.ps1",
  "status": "stopped",
  "exitCode": 3,
  "startedAt": "2026-09-30T10:15:00+09:00",
  "finishedAt": "2026-09-30T10:15:42+09:00",
  "inputs": {
    "template": "work/edit-01/application.xlsm",
    "source": "src",
    "outDir": "work/build-20260930-1",
    "commit": "abc1234",
    "uncommittedChanges": true
  },
  "checks": [
    { "name": "codepage-932", "result": "pass" },
    { "name": "template-no-code", "result": "fail", "detail": "ひな形に Module1 が残っている" },
    { "name": "compile", "result": "not-run", "detail": "人による確認の対象" }
  ]
}
```

- `status` は `success`・`failed`・`stopped`・`env-error`・`timeout`・`error` のいずれかで、終了コードと対応させます。
- `inputs` には実際に使ったパスを記録し、どのファイルから作ったかを後から確認できるようにします。
- 各確認の `result` は `pass`（合格）・`fail`（失敗）・`not-run`（未実施）のいずれかです。未実施を合格として扱わず、`detail` に理由を書きます。
- `result.json` がない場合は、処理が途中で異常終了したものとして扱います。

### Excelの後始末

- スクリプトは起動直後に、処理専用のExcelのプロセスID（`Application.Hwnd` から取得）を `<OutDir>` に記録します。
- 成功しても失敗しても、最後に自分で開いたブックを閉じ、Excelを終了します。

### タイムアウト

タイムアウトの目的は、処理の長さを制限することではなく、**Excelがダイアログなどで固まり、処理が進まなくなったことを検知する**ことです。モジュールやテストが増えると全体の時間は延びますが、一つ一つの操作は短時間で終わります。そこで、全体の所要時間ではなく、**進捗が止まっている時間**で判定します。

Excelが固まるとCOMの呼び出しが戻らず、本体のスクリプトは自分でタイムアウトを判定できません。そのため、見張り役の `invoke-with-timeout.ps1` が本体を別のプロセスとして起動して監視します。

1. 本体は、手順を一つ終えるたびに `<OutDir>/progress.json` を更新します（例：「AppMain.bas をImport完了」「テスト 3/12 完了」）。
2. 見張り役は `progress.json` の更新時刻を監視します。
3. 次のどちらかに当たったら、本体と記録したプロセスIDのExcelだけを終了し、`result.json` を `timeout` にして終了コード5を返します。ユーザーが開いているExcelは終了させません。

| 引数 | 既定値 | 意味 |
|---|---|---|
| `-StallTimeoutSec` | 120 | 進捗がこの秒数止まったらタイムアウト |
| `-TotalTimeoutSec` | 1800 | 全体の上限。無限ループなどへの最後の安全策 |

- 既定値は仮の値です。初回の実機検証（第8節）で各手順の所要時間を記録し、最も遅い手順の3〜5倍程度に合わせて見直します。
- 1件で長時間かかるテストがある場合は、そのテストに個別の制限時間を設けるか、テストの途中でも進捗を書き込みます。
- タイムアウト時の `result.json` には、`progress.json` の最後の記録（どの手順で止まったか）を含めます。

### コンパイル確認

COMにはコンパイルの成否を返す手段がなく、VBEのコンパイル操作はエラー時にダイアログを出して止まります。当面は人が確認する項目とし、`result.json` では `compile` を `not-run` として返します。

## 11. AIエージェントの作業規則

AIエージェントがこのプロジェクトで作業するときの規則です。本書は「守る規則」を、`skills/` のスキルは「作業の手順」を扱います。

### 自分の判断で行ってよいこと

**プロジェクトのフォルダ内での作業は、下の「禁止すること」を除いて、基本的にすべて自分の判断で行ってかまいません。** ファイルの作成・編集、スクリプトの作成・実行を含みます。主な例は次のとおりです。

- `src/` の `.bas`・`.cls`・`.vba` と、`.frm` のコード部分（`Attribute` 行より後ろ）を編集する。`.frm` のヘッダー部分は変更しない。
- `scripts/`・`bootstrap/`・`tests/`・`docs/` を編集する。
- `build.ps1`・`verify.ps1`・`export-edits.ps1`・`describe-forms.ps1` を実行する。
- フォームやひな形のコピーをCOM経由で編集するための、一回限りのスクリプトを `work/` に書いて実行する。
- `work/` の下に新しいフォルダやファイルを作る。
- 終了コード2（検証の失敗）の原因を調べ、`src/` を修正して再実行する。同じ失敗が3回続いたら止まって報告する。

Excelを操作するときは、既存のスクリプトでも一回限りのスクリプトでも、次を守ります。

- 第2節の開き方に従う（処理専用のExcel、組み立て・編集はマクロ無効）。
- `invoke-with-timeout.ps1` を通して実行する（第10節）。
- 編集の対象は `work/` へコピーしたブックとし、`templates/` や `dist/` のブックを直接開いて書き換えない。
- フォームの画面を編集するときは、編集の前後で部品一覧を書き出し、差分をユーザーに示す（第6節）。

### 禁止すること

- `.frx` を直接編集する。フォームの画面の変更はExcel内のフォームをCOM経由で操作する（第6節）。
- `templates/` を直接上書きする。ひな形の採用は人の確認後に行う（第7節）。
- 本番データ・バックアップ・正式配布物の保管先にアクセスする。
- `work/`・`dist/` のファイルを削除する。整理は人が行う。
- ユーザーが開いているExcelを操作・終了する。
- `result.json` で `fail` や `not-run` になっている項目を、合格として報告する。
- タイムアウトしたときに、制限時間を延ばして再実行する。固まった原因はダイアログなどである可能性が高く、時間を延ばしても解決しないため。
- 未コミットの変更を含んだ状態でビルドしたブックを、ユーザーに渡す（第8節）。

### 止まって人に確認すること

- 終了コード1・3・4・5が返ったとき。`result.json` の内容を添えて報告する。タイムアウト（5）の場合は、どの手順で止まったか（`progress.json` の最後の記録）も伝える。
- `export-edits.ps1` で、新規追加・削除された部品が見つかったとき（第9節）。
- 三者比較で、ユーザーの変更と現在の正本の変更が衝突したとき（第9節）。
- 依頼の意図と、正本や要件書の内容が食い違うとき。

### 完了の条件

作業の完了を報告するのは、次をすべて満たしたときです。

- 最後に実行したスクリプトの終了コードが0である。
- `result.json` の全項目が `pass`、または `not-run` の理由が書かれている。
- `not-run` の項目と、`tests/acceptance.md` のうち人による確認が必要な項目を、ユーザーに伝えている。

人による確認が済んでいない場合は「完成」ではなく「自動確認まで完了」と報告します。

## 12. 版管理と復元

変更前の一式を残し、正本を直接上書きせずに次版候補を作ります。例えば現在の版が `v003` なら、それは変えずに `v004` の候補を作ります。確認に失敗したら候補を破棄し、採用後に問題が見つかったら過去版へ戻せるようにします。

### 版番号

- 版番号は `v001`、`v002` … の連番（3桁）とし、ユーザーへ発行するたびに1ずつ上げます。変更の大きさで番号の付け方を変えません。
- 版番号を付けるのは、検証に合格して発行するブックだけです。それ以外の候補は版番号を持たず、コミット番号で区別します。
- 発行するときは `build.ps1` に `-Version v004` を渡します。ブックには、ユーザー設定のドキュメントプロパティ `AppVersion` として記録します（`SourceCommit` と並べて記録。第9節）。`-Version` を省略した場合は `dev` と記録し、発行物ではないことが分かるようにします。
- 発行したコミットには、同じ名前のGitタグ（`v004`）を付けます。
- 配布物のファイル名に版番号を付けます（例：`application_v004.xlsm`）。
- `docs/release-notes.md` に、版番号・日付・変更内容・確認結果・元のコミットを1版ずつ記録します。
- 画面上のどこに版番号を表示するかは、案件ごとに決めます。

### 版ごとに残すもの

- Excelひな形
- VBAソース
- `.frm`＋`.frx`
- 変更メモと元の版
- 必要に応じて、その版の配布用ブック

- Gitでは、ひな形・コード・フォームがそろった状態を一つのコミットとして記録し、コミットやタグから一式を取り出せるようにします。版ごとにフォルダを複製する必要はありません。
- ひな形や `.frx` は細かい差分確認や部分的な取り消しが難しいため、ブック全体の保存と表示確認を併用します。
- 「過去版へ丸ごと戻す」と「一部の変更だけ戻す」を区別し、後者は新しい修正として扱います。
- シートとコードに依存関係がある場合、片方だけ古い版に戻しません。
- 当面は、複数の人やAIが同時に編集せず、一度に一つの変更を進めます。

## 13. 本番データとの関係

本書の仕組みが管理するのは、ひな形・コード・フォームです。業務データの保存構成（ブックを分けるか、どこに保存するか、同時更新をどう扱うか）は、案件ごとの設計で決めます。本書では、仕組みの都合で案件側が知っておくべき点だけを挙げます。

- **新版はひな形から作り直します。** 発行済みブックの中に保存されたデータは、新版のブックには引き継がれません。データをブック内に持つ設計にする場合は、案件側でデータの引き継ぎ方法を用意します。
- **版を戻してもデータは戻りません。** 本書の復元（第12節）で戻るのは、ひな形・コード・フォームだけです。
- **実データを開発フォルダに入れません。** ひな形・ソース・テスト用データに、実業務データや端末固有の秘密情報を含めません。コード・フォームの取り込みやひな形の編集でも、一緒に入り込んでいないか確認します。

## 15. 要約

- 標準モジュールは `.bas`、独自クラスは `.cls`（属性を含む）、ThisWorkbook・シートは本文の `.vba`、フォームは初回生成後の `.frm`＋`.frx` を正本とする。
- シートの見た目・構造はコードのないExcelひな形を正本とし、変更はひな形側で行う。発行済みブックのシート編集は取り込まない。
- ひな形にコードを持たせず、VBA部品は原則すべて管理対象とする。想定外の部品や対応漏れがあれば停止する。
- Windows端末の対話セッションで、処理専用のExcelを使って実行する。組み立て・抽出はマクロ無効、動作検証はマクロ有効で工程を分ける。
- リポジトリはUTF-8（BOMなし）・CRLF、ExcelとはCP932で変換し、変換できない文字があれば停止する。
- Excel内で直接変更したコード・フォームは、書き出して比較し、採用する変更だけ正本へ戻す。比較元はブックに記録したコミットとし、ユーザーに渡すブックはコミット済みの状態から作る。
- 追加の参照設定は使わず、外部ライブラリは `CreateObject` で呼び出す。
- 版管理には社内で承認された環境を使い、公開リポジトリは使わない。
- ThisWorkbook・シートのモジュールではプロシージャ単位の属性を使わない。名前の大文字小文字だけの差分は採用しない。
- フォームを編集するときは、前後の部品一覧を書き出して変更を確認する。Exportは拡大率100%の端末で行う。
- スクリプトは実行ごとに変わるパスを必須の引数で受け取り、終了コードと `result.json` で結果を返す。
- AIエージェントは第11節の規則に従い、人の判断が必要な場合と完了条件を満たさない場合は止まって報告する。
- 変更前の一式を残し、次版候補で確認してから新版を発行する。業務データの保存構成は案件ごとに決め、実データを開発フォルダに入れない。
